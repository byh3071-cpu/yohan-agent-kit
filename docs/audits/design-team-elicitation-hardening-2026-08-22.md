# 디자인 팀 실전 적용 감사 — 2026-08-22

## 결론

`design-team`을 첫 실제 프로젝트에 적용해 시안을 세 벌 만들었고 전부 거절됐다. 문제는 거절이 아니라 **계약이 그 실패를 하나도 예방하지 못했다**는 점이다. Goal 11·12는 절차·역할·기록·수치 검증을 갖췄지만, 그 절차를 **건너뛰어도 아무것도 막지 않았다.** Goal 13은 건너뛸 수 없게 만든다.

## 실전에서 드러난 것

| 무슨 일이 있었나 | 계약이 왜 못 막았나 |
| --- | --- |
| 레퍼런스 1건 상태로 시안 제작이 진행됐다 | "취향 기록 없으면 시각화 금지"는 있었으나 **레퍼런스 조항은 없었다**. Gather 단계가 통째로 생략 가능했다 |
| 대조군이 실제 제품보다 조악했다 | 후보의 품질 기준이 없었다. 디렉터는 두 실패 중 하나를 고르게 됐고 답은 노이즈가 됐다 |
| 금지 패턴 스캔이 "통과"를 반환했다 | 목록이 비어 있었다. **빈 목록은 항상 통과한다** |
| 두 축에서 "둘 다 별로"가 나왔다 | 처리 규칙이 없어 같은 축을 반복할 뻔했다. 실제 원인은 두 안이 공유한 전제였다 |
| 시안이 전부 균등하게 밋밋했다 | 무엇이 덜 중요한지 몰라 모든 요소를 같은 무게로 배치했다. **강약은 죽이는 데서 나온다** |
| 디렉터가 "이 화면이 뭘 해결하려는지 애매하다"고 지적했다 | 목적 미정 상태에서 시각화로 진입하는 것을 막는 조항이 없었다 |
| 상담지를 매번 손으로 짜다 저작 규율을 어겼다 | 상담지 제작 방법이 계약에 없었다 |
| 1차 상담지는 선택이 진행자에게 돌아오지 않았다 | 회수 경로 요구가 없어 디렉터가 고른 것을 다시 물어야 했다 |
| 레퍼런스에서 규칙만 뽑고 레이아웃은 매번 새로 설계했다 | 골격 차용 조항이 없었다. 규칙을 다 지키고도 밋밋한 전형적 결과가 나왔다 |
| 팀이 만든 대조군이 팀이 등록한 금지 패턴을 두 번 위반했다 | 스캔 범위가 "최종 산출물"로 읽혔다. 작업용 산출물이 사각지대였다 |
| 색조 기반 검사 규칙이 두 번 틀렸다 | 규칙을 거절된 실물로 교정하라는 요구가 없었다. 설명에서 유도한 테스트는 오탐·미탐한다 |

## 설계 판단

1. **건너뛸 수 있는 절차는 절차가 아니다.** Goal 11·12는 "무엇을 하라"를 규정했고, Goal 13은 "무엇 없이는 다음으로 못 간다"를 규정한다. 게이트 문장을 SKILL 본문에 둔 이유다.
2. **팀의 작업용 산출물도 산출물이다.** 대조군·상담지는 임시로 느껴져 검사에서 빠지지만, 디렉터가 다음으로 보는 것이 정확히 그것이다. 거절한 패턴이 거기서 다시 나오면 원래 실수보다 신뢰를 더 깎는다.
3. **거절은 데이터고, "둘 다 거절"은 축 설계의 실패 신호다.** 두 안이 공유한 전제가 실제 발견이며, 같은 축을 장식만 바꿔 재질문하는 것은 시간 낭비다.
4. **강약은 배치가 아니라 제거에서 나온다.** 중요도 순위를 디렉터에게 받지 않으면 팀은 직관으로 강조를 정하게 되고, 그 직관을 배제하는 것이 이 스킬의 존재 이유다.
5. **목적이 안 서면 시각 옵션은 배치만 다른 세 개가 된다.** 그때 필요한 건 스타일 경쟁이 아니라 목적 경쟁이며, 무엇이 화면에 있느냐로 차이를 낸다.
6. **규칙과 골격은 함께 가져와야 한다.** 골격은 원본 팀이 가장 오래 걸려 얻은 부분이고, 규칙만 베끼면 준수하되 밋밋한 결과가 재현된다.
7. **검사 규칙은 거절된 실물로 교정한다.** 실패를 한 번도 낸 적 없는 검사는 교정되지 않은 검사다.

## 범용성 유지 근거

- 실전 프로젝트의 취향 값·레퍼런스·화면 진단은 전부 프로젝트 소유 인수인계로 분리했고 스킬에 넣지 않았다.
- 특정 도구·제품·벤더 이름을 조항에 넣지 않았다. 상담지 제작은 "런타임과 프로젝트가 제공하는 저작 도구"로만 규정한다.
- 매체 중립을 유지했다 — 상담지는 문서·보드·인쇄물·화면 중 무엇이든 될 수 있고, 회수 경로 요구도 매체별로 열려 있다.
- 검사기가 제품명·벤더명·색상 하드코딩을 강제로 막는다.
