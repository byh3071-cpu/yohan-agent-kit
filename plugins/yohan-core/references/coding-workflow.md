# 코딩 작업의 공통 실행 기준

정본: Agent Kit `plugins/yohan-core/references/coding-workflow.md`. Codex·Claude Code의 짧은 공통 지침은 이 기준을 따른다. 매 작업마다 이 파일을 다시 읽거나 동기화할 필요는 없다.

- 대화와 기존 코드에서 원하는 완료 상태와 승인 범위를 파악한다. 소스 수정·개발용 반영·Draft PR·머지·프리뷰 발행을 구분하며, 결과를 바꾸는 불명확한 점만 질문한다. 한 번 승인된 범위의 읽기·수정·필요한 검사·안전한 보정은 이어서 끝낸다.
- 수정 위치·기대 동작·유지할 호환성·확인 방법이 정해지면 구현한다. 기존 조사 결과를 재사용하며 새 오류·미해결 가정·의존성이 있을 때만 추가 조사한다.
- 변경 영향에 필요한 직접 확인·관련 테스트를 수행한다. 파일 수만으로 위험을 판단하지 않는다. 인증·결제·데이터·공유 인터페이스처럼 영향이 넓으면 필요한 검사를 넓힌다. 기존 필수 CI는 유지한다.
- 관련 코드·테스트·입력·의존성·환경이 그대로라면 통과한 결과를 재사용한다. commit·PR·보고 단계가 바뀌었다는 이유로 재검사하지 않는다. 충돌 해결·변경·실패가 영향을 준 부분만 다시 확인한다. 명령이 전체 검사나 빌드를 포함하면 중첩 실행을 피한다.
- 개발용 반영이 승인 범위라면 실제 실행 소스와 빌드 경로를 확인하고 필요한 빌드·재시작·핵심 동작 확인까지 마친다. 소스나 PR만 바뀐 상태를 실행 앱에 적용됐다고 보고하지 않는다. 사용자 변경과 세션은 보존한다.
- 코드는 동작의 정본이다. 코드·Git으로 복원할 수 없는 이유·운영 제약·미완료 지점만 목적에 맞는 기존 기록 한 곳에 남긴다. 매 작업 Dev Log·교훈·패턴·ADR, QA 보고서·증거 묶음·내보내기 스크립트를 자동 생성하지 않는다.
- 공통 지침은 실행 판단, 프로젝트 지침은 명령·구조·환경·필수 CI, 스킬은 해당 작업의 전문 지식과 도구 사용법을 맡는다. 키워드만으로 여러 스킬을 연쇄 호출하거나 각 계층의 계획·검사·문서·리뷰를 누적하지 않는다. VHK는 문제 해결과 사용자 재개 승인 전까지 실행·설치·업데이트·동기화까지 전면 보류한다. 강제 검증 스킬·평가 로그·자동 모델 검토로 대체 호출하지 않는다.
- 새 프로젝트는 선택한 프레임워크와 실행 명령으로 시작한다. 하네스·Notion·빈 기록 체계를 기본 설치하지 않는다. 추가 도구는 구체적인 문제와 사용자 승인 범위가 있을 때만 도입한다.
- 포맷은 변경 묶음 끝에 필요한 파일에 기존 프로젝트 명령으로 수행한다. 매 편집 포맷, 세션 종료 동기화·라우팅 검사·원격 기록, 매 프롬프트 제목 처리는 자동 절차로 두지 않는다.
- 제목 도구가 있으면 새 세션의 첫 의미 있는 요청에서 Asia/Seoul 기준 `MM.DD 핵심 주제`로 한 번 설정한다. 사용자 제목이나 이미 설정한 제목은 보존한다.
- 승인된 변경·필요한 확인·요청된 적용을 마치면 결과·확인 여부·미완료 사항을 짧게 보고하고 종료한다. 새 근거 없이 리뷰·문서·조사·검사를 추가하지 않는다.
- 시크릿 보호와 파괴적 작업 가드를 유지한다. 삭제·대규모 이동·새 외부 전송·유료 호출 확대·전역 설치/홈 변경·PR Ready·merge·배포·publish는 기존 승인 경계를 따른다. 모델·기본 추론 강도는 자동 변경하지 않는다.
