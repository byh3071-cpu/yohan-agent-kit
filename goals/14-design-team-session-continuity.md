# Goal 14: 디자인 팀 세션 연속성·운영 인수인계

## 배경

Goal 11–13은 프로젝트 컨텍스트, 취향 상담, 레퍼런스와 검증 계약을 만들었지만 실제 장기 디자인 세션을 끝내고 독립 세션으로 넘길 때 필요한 복원 계약은 부족했다. 그 결과 보고서를 쓴 상태와 대상 세션이 실제로 받은 상태가 섞이고, 짧은 진행 동의가 최종 승인처럼 해석되며, 이미지가 사용자에게 보이지 않았는데도 선택을 요구할 수 있다.

## 범위

- 프로젝트가 소유하는 디자인 세션 인수인계 최소 번들
- 새 지휘자의 첫 응답과 정확한 재개 지점 계약
- 진행 동의·방향 선택·최종 승인 상태 분리
- 시각 산출물의 표시·안정 경로·사용자 가시성 영수증
- 작성·전송·수신 확인을 분리한 전달 영수증
- 디자인 디렉터용 운영 매뉴얼의 세션 시작·종료 절차
- 실제 프로젝트 forward test와 프로젝트 고유 취향 데이터 분리

## 비범위

- 특정 프로젝트의 색·폰트·레이아웃·말투를 범용 스킬에 하드코딩
- production UI 구현
- 사용자 홈 스킬 설치·릴리즈·main 직접 push·자동 머지
- Orca 또는 다른 세션 런타임 자체의 결함 수정

## Completion Check

- [ ] `session-continuity.md`가 필수 번들, 시작 handshake, 종료 receipt, 실패 복구를 규정한다.
- [ ] 짧은 진행 동의가 취향 규칙·최종 승인으로 승격되지 않고 승인 단계가 명시적으로 분리된다.
- [ ] 다음 세션은 해결된 질문을 반복하지 않고 정확한 다음 사람 게이트에서 대화를 시작한다.
- [ ] 이미지·시안은 실제 표시와 안정 경로가 확인되기 전 선택을 요구하지 않는다.
- [ ] 보고서 작성·전송 시도·대상 수신 확인이 서로 다른 상태와 근거를 가진다.
- [ ] 운영 매뉴얼·SKILL·context·report·team 계약이 같은 세션 연속성 모델을 사용한다.
- [ ] 실제 프로젝트 forward test의 취향값·경로는 프로젝트 저장소에만 남는다.
- [ ] 스킬 validator, manifest, registry/catalog, Goal 11–13 회귀 게이트가 통과한다.

## Forbidden

- 프로젝트 고유 취향·대화 원문·개인 경로를 공통 스킬에 축적
- 대상 세션 ACK 없이 `전달 완료`라고 보고
- `ㅇㅇ`, `계속`, `진행` 같은 짧은 답을 최종 디자인 승인으로 간주
- 이미지 생성 성공을 사용자 가시성 확인으로 간주
- 홈 설치·배포·push·merge를 암묵적으로 수행
