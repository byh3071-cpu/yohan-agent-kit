# Goal 12: 디자인 팀 취향 상담·레퍼런스 수집·수치 검증 계약

## 배경

Goal 11의 `design-team`은 운영 절차·역할·보고 규격을 갖췄지만, 디자인 디렉터의 취향을 **묻는 절차도 담는 자리도** 없었다. 그 결과 시안이 매번 백지에서 출발해 밋밋하게 나오고, "측정 가능한 검사"는 문장으로만 존재해 검증이 눈대중으로 끝난다. 레퍼런스 수집도 역할표에 이름만 있고 절차가 없다.

이 Goal은 스킬을 갈아엎지 않고 빠진 4개 계약을 물린다.

## 범위

- 실물 후보 비교로 취향을 뽑고 역추출·확인까지 가는 상담 계약
- 질문 기반 레퍼런스 수집·채택 게이트·금지 패턴 동등 수집 계약
- 매체별 실측 임계값과 금지 패턴 스캔을 포함한 검증 계약
- DesignContext의 취향 칸 신설 (규칙·금지 패턴·레퍼런스 3종 기록 형식)
- 디자인 디렉터가 읽는 운영 매뉴얼
- SKILL·team·report 계약에 Elicit·Gather 단계와 취향 인터뷰어 역할 반영

## 비범위

- 특정 프로젝트의 취향 값·레퍼런스 자산 축적 (프로젝트 소유)
- 관제탑 UI 구현·시안 제작
- 이미지 생성 도구 배선
- Goal 11 계약의 재작성

## Completion Check

- [x] 취향 상담 계약이 실물 후보 3종 출처, 축 상한, 한 번에 한 축, 역추출 확인, 세션 예산을 규정한다.
- [x] 수집 계약이 출처 등급, 질문 선행, 사람 채택 게이트, 금지 패턴 동등 수집, 권리·보관을 규정한다.
- [x] 검증 계약이 판정 기록 6필드, 매체별 기본 임계값, 금지 패턴 스캔, 실패 처리, 규제 분리를 규정한다.
- [x] DesignContext에 취향 칸과 3종 기록 형식이 있고 미확인 추론의 승인 사용을 금지한다.
- [x] 운영 매뉴얼이 사람 게이트와 오작동 대처를 디자인 디렉터 언어로 규정한다.
- [x] SKILL에 Elicit 모드·단계, Gather 단계, 취향 없는 시안 생성 금지가 있고 신규 계약 4개를 참조한다.
- [x] 스킬 전체에 프로젝트 고유 사실·미학·고정 모델·머신 경로 하드코딩이 없다.
