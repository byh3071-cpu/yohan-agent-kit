# Design to HTML

- 요청한 사용자 행동, 대상 화면, 기대 결과를 대화와 기존 코드에서 파악한다. 사용자에게 디자인 용어로 재설명을 요구하지 않는다.
- 선택한 시안·명확한 시각 기준이 있으면 그것을 따르고 프로젝트의 컴포넌트·토큰·자산을 재사용한다. 화면이 없다는 이유만으로 별도 탐색 스킬·인터뷰를 강제하지 않는다.
- 방향이 실제로 불명확하면 필요한 부분만 작게 비교한다. 분위기·배치는 같은 콘텐츠와 화면 크기의 이미지 또는 기존 캔버스, 동작은 기존 앱의 핵심 흐름을 사용한다. 전체 앱 여러 벌을 만들지 않는다.
- 기존 앱에는 해당 프레임워크로 구현한다. 독립 HTML은 사용자가 요청하거나 독립 시연이 실제로 더 간단할 때 선택한다. 모든 후보의 HTML을 다시 생성하지 않는다.
- 실제 문구와 대표 데이터를 넣고 주요 행동이 끝까지 동작하게 한다. 불필요한 기능·설명·장식과 사용자가 제외한 요소를 추가하지 않는다.
- 변경한 동작과 영향을 받는 화면 크기·키보드·오류 상태를 직접 확인한다. 레이아웃이 변하면 대표 모바일·데스크톱부터 보고 문제나 요구가 있을 때만 범위를 넓힌다.
- 소스와의 시각 비교가 필요하면 같은 화면 크기·상태로 확인한다. 통과한 변경 없는 부분의 검사를 반복하지 않는다.
- 결과·확인한 범위·남은 문제를 짧게 전달한다. 별도 비교 사이트, design-qa.md, 점수·증거 묶음·commit SHA를 완료 조건으로 강제하지 않는다. Git·배포는 승인된 범위만 수행한다.

출처 충돌이 있을 때만 `references/context-contract.md`, 확인 범위가 불명확할 때만 `references/quality-gate.md`를 참고한다. Notion·VHK·자동 평가 모델은 호출하지 않는다.
