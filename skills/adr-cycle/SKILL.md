# ADR 사이클

결정을 바로 문서화하기 전에 ADR이 필요한지부터 판정한다. 프로젝트의 기존 기록 규약을 보존하고, 새 ADR은 사람 승인 전까지 `Proposed`로 유지한다.

## 컨텍스트와 기록 규약을 찾는다

다음 순서로 필요한 범위만 조사한다.

1. 현재 파일에서 가장 가까운 `AGENTS.md`, `CLAUDE.md`, `RULES.md`
2. 기존 ADR 디렉터리·인덱스·템플릿·decision log와 Git 이력
3. 생태계 공통 결정이면 연결된 brain의 계약·ADR
4. 현재 대화와 사용자가 직접 제공한 과거 자료

Notion은 감사·정리 요청에 필요하고 테스트 API 호출로 인증이 확인된 경우에만 보조 증거로 읽는다. 과거 ChatGPT 대화에 자동 접근할 수 있다고 가정하지 않는다. Git 결정, 대화, Notion이 충돌하면 확정 사실, 제안, 미해결 충돌로 분리한다.

## ADR 필요성을 판정한다

다음 질문 중 여러 개가 참이면 ADR 후보로 본다.

- 결정이 여러 구성요소·프로젝트·에이전트에 영향을 주는가?
- 나중에 되돌릴 때 데이터 이전, 호환성, 보안, 큰 재작업 비용이 드는가?
- 책임·정본·인터페이스 경계를 오래 유지해야 하는가?
- 대안과 기각 이유를 미래 작업자가 알아야 하는가?

단순 설명, 작은 리팩터링, 쉽게 되돌릴 수 있는 운영 선택이면 파일을 만들지 않는다. 프로젝트의 decision log를 사용하거나 위치·형식을 제안한다. 기존 규약이 없으면 새 폴더·번호·상태 체계를 몰래 만들지 않는다.

## 작업 유형을 정한다

| 요청 | 동작 |
|---|---|
| 새 결정 | 다음 번호와 템플릿을 확인하고 `Proposed` 초안을 만든다. |
| 검토 | 결정 근거·대안·결과·상태·관련 ADR의 일관성을 검사한다. |
| 승인 | 사용자의 명시 승인과 프로젝트 규약을 확인한 뒤 상태만 전이한다. |
| 대체 | 새 ADR을 작성하고 기존 Accepted ADR을 `Superseded`로 연결한다. |
| 폐기 | 실제 수명주기와 근거에 맞춰 `Deprecated` 또는 프로젝트 규약의 상태를 사용한다. |

Accepted ADR의 실질 결정을 본문에서 몰래 고치지 않는다. 오탈자·끊어진 링크 같은 비의미 수정이 아니라면 새 ADR로 대체한다. 검토나 상태 전이를 수행할 때 [수명주기·검토 체크리스트](references/review-checklist.md)를 읽는다.

## 조사하고 초안을 작성한다

1. 결정 질문, 범위, 결정 동인, 제약, 이해관계자, 되돌리기 비용을 확인한다.
2. 저장소·기존 ADR·커밋·공식 문서에서 근거를 모으고 출처와 확인일을 남긴다.
3. 프로젝트 템플릿을 우선해 맥락, 결정, 결과, 대안을 작성한다.
4. 실제로 검토한 대안만 적고 표를 채우기 위한 가짜 대안을 만들지 않는다.
5. 장점뿐 아니라 비용, 운영 부담, 마이그레이션, 미해결 위험을 결과에 포함한다.
6. 관련·충돌·대체 ADR과 구현 전제조건을 링크한다.
7. 새 ADR의 frontmatter와 본문 상태를 모두 `Proposed`로 맞춘다.

yohan-brain에서는 기존 3자리 대문자 파일명, 필수 frontmatter, `Proposed` 기본값을 유지한다. ADR이 과한 작은 운영 결정은 기존 `memory/decisions/` 규약을 따른다.

## 사람 게이트에서 멈춘다

- 에이전트는 새 ADR을 자동으로 `Accepted`로 만들지 않는다.
- `Proposed` ADR을 근거로 조사·계획은 할 수 있지만, 그 결정에 의존하는 구현은 시작하지 않는다.
- 승인 요청에는 ADR 경로, 결정 한 줄, 주요 대안, 되돌리기 비용, 미해결 위험을 함께 제시한다.
- 명시 승인 뒤에도 main/master 머지나 배포는 별도 게이트로 남긴다.

## 승인 뒤 goal-cycle로 넘긴다

Accepted가 확인되면 다음 악수 블록을 `$goal-cycle` 입력으로 전달한다.

```text
ADR 경로: <repo-relative path>
상태: Accepted
확정 결정: <한 줄>
제약: <목록>
후속 작업: <목록>
미해결 위험: <목록 또는 없음>
```

v1에서는 원 대화의 맥락을 가진 주 에이전트가 초안을 작성한다. 큰 ADR에서만 선택적으로 다른 눈 검수를 붙이며, 검토자가 자동 승인자가 되지는 않는다.
