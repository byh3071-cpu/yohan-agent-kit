> **2026-10-07 전면 보류 적용:** VHK의 실행·설치·업데이트·주입·동기화·Goal/verify/receipt/review·watch·autopilot은 문제 해결과 사용자 재개 승인 전까지 중단한다. 아래 과거 절차의 강제 검토·검증 스킬·Evaluator·평가 로그·자동 모델 호출·중복 기록 요구는 적용하지 않는다. 추가 검토는 해당 작업의 명시 요청이 있는 경우에만 선택한다. 사용자 변경·시크릿 보호·사람 승인 경계는 유지한다.

# 골 사이클

사용자가 승인한 큰 목표를 필요한 단계로 나누어 끝낸다. 기본 모델·추론 강도는 바꾸지 않는다. 이 스킬 자체가 새 Goal 생성이나 추가 서비스 설치의 승인은 아니다.

## 필요한 맥락과 완료 범위

- 현재 대화, 적용되는 프로젝트 지침, 관련 코드·Git 상태·실행 명령을 필요한 만큼 읽는다. 관련 없는 로스터·용어집·운영 문서를 필독하지 않는다. 생태계 도구를 실제 사용할 때만 [운영 참고](reference.md)의 해당 부분을 읽는다.
- 소스 수정·개발용 반영·Draft PR·머지·프리뷰 중 승인된 완료 범위를 파악한다. 결과에 영향을 주는 누락만 질문하며 이미 승인한 실행을 단계마다 다시 승인받지 않는다.
- 수정 위치·기대 동작·호환성·확인 방법이 정해지면 구현한다. 기존 조사 결과를 재사용하고 새로운 오류·미해결 가정·의존성이 있을 때 추가 조사한다.

## 결정과 승인 경계

- 되돌리기 비싼 미확정 책임·데이터·인증·기술 선택은 관련 결정과 사용자 지시를 확인한다. 실제로 미승인인 결정에 의존하는 작업만 보류하고 독립 작업은 진행한다. 사용자의 현재 승인을 과거 문서 상태만으로 부정하지 않는다.
- ADR 절차를 사용자가 요청했거나 해당 프로젝트의 구체적인 미해결 결정에 필요할 때만 적용한다. 모든 큰 목표에 ADR이나 별도 계획 파일을 만들지 않는다. 기존 ADR을 사용하면 대체·철회·제약과 미해결 위험을 확인한다.
- 시크릿, 삭제·대규모 이동, 새로운 외부 전송, 유료 확대, 전역 설치·홈 변경, PR Ready·merge·배포·publish의 승인 경계를 지킨다. 계획에 승인된 범위는 안전한 보정과 관련 검사까지 이어서 수행한다.

## 필요한 단계로 실행

1. 완료 조건·의존성·남은 사람 게이트를 짧게 정한다. 여러 작업이 얽힐 때만 계획과 담당을 나눈다. 범용 S/M/L 선언이나 별도 체크리스트 파일을 요구하지 않는다.
2. 승인 범위를 작은 동작 단위로 구현한다. 독립 작업 위임이 유용하면 소유 파일·결과를 명확히 나누고 다른 담당자의 변경을 보존한다. 검수 역할·실행 공급자·별도 평가 모델을 자동으로 추가하지 않는다.
3. 변경 영향에 필요한 직접 확인·관련 테스트를 수행한다. 인증·데이터·공유 인터페이스처럼 영향이 넓으면 검사도 넓힌다. 필수 CI는 유지하되 작은 변경에 전체 로컬 검사·실패 테스트 선행·전체 E2E를 일률적으로 요구하지 않는다.
4. 관련 코드·테스트·입력·의존성·환경이 같은 통과 결과를 재사용한다. commit·PR·보고 단계가 바뀌었다는 이유로 반복하지 않는다. 새 변경·충돌 해결·실패가 영향을 준 부분만 다시 확인한다.
5. 개발용 반영이 승인됐다면 실제 실행 경로와 빌드·재시작·핵심 동작을 확인한다. Git 처리는 승인 범위에서 수행하며 소스/PR 상태와 실행 앱 상태를 구분한다.
6. 완료 조건을 충족하면 결과·직접 확인·남은 승인 단계만 보고하고 종료한다. 근거 없이 리뷰·관찰·추가 조사·문서를 늘리지 않는다.

## 도구와 기록

- Orca·오케스트레이션·후속 관찰은 해당 작업에서 실제 선택된 경우에만 현재 계약을 확인한다. 설치되지 않은 실행 공급자를 필수 전제나 자동 폴백으로 만들지 않는다. 필요한 인증·권한이 없으면 의존 작업만 미완료로 보고한다.
- VHK·cross-check·release-gate·Evaluator·적대적 리뷰 반복·검증용 모델 호출을 자동 실행하지 않는다. 사용자가 명시한 절차와 변경에 필요한 직접 확인만 수행한다.
- 코드·테스트·Git이 기본 정본이다. 코드에 없는 결정 이유·운영 제약·인수인계가 실제로 필요할 때 소유 프로젝트의 기존 기록 한 곳에 남긴다. 매 작업 Dev Log·교훈·패턴·QA 보고서·증거 스크립트 생성, Notion 조회·전송, 자동 문서 역전파를 요구하지 않는다.
- 상태 보고는 필요한 사실만 쓴다. 단계표·성공 점수·악수·리스크표·투입 AI표를 기본 형식으로 강제하지 않는다.
